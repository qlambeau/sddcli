# Architecture Decision Record

## Context

US-006 adds the first mutating workflow capability to a Rust workspace that
currently reads and validates SDD artifacts only. Promotion must preserve the
pure domain boundary, update only lifecycle metadata, remain deterministic in
tests, and never leave a partially written artifact. The existing
`ArtifactSource` and `ArtifactIdentitySource` contracts do not provide a safe
write seam and must remain compatible for existing validators.

Promotion also needs to preserve Markdown body content and Gherkin content while
updating status and the latest promotion metadata. A failed or concurrent write
must not silently overwrite a newer artifact version.

## Decision

1. Keep promotion policy in a pure domain evaluator. It receives normalized
   artifact state, validated promotion facts, the requested target, actor
   identity, and a supplied timestamp, and returns an accepted plan, an active
   same-state no-op, or ordered diagnostics.
2. Define an application-owned `ArtifactPromotionStore` port for reading the
   target's original source and committing an approved promotion plan. The port
   accepts an expected original source value so a changed artifact is rejected
   as a conflict before replacement.
3. Define an application-owned `Clock` port so timestamp generation is injected
   and deterministic test doubles can be used. The production composition root
   supplies the system clock when the CLI is introduced.
4. Implement the filesystem store in the existing artifact-filesystem adapter.
   It patches only lifecycle status and the latest promotion metadata, writes a
   temporary file in the target's directory, and replaces the target with an
   atomic same-directory rename. It never moves an artifact between locations.
5. Store the latest promotion record as four scalar fields:
   `promoted_from`, `promoted_to`, `promoted_by`, and `promoted_at`. Markdown
   artifacts store them in frontmatter; Gherkin artifacts store equivalent
   comment headers. A real transition replaces the previous record, while an
   idempotent same-state request writes nothing.
6. Represent `promoted_at` as UTC Unix seconds. This keeps the value scalar and
   avoids introducing a time-formatting dependency into the workspace.
7. Keep CLI parsing, exit codes, machine-readable serialization, release-record
   promotion, and packet-level transactions outside this slice.

## Alternatives Considered

| Alternative | Reason not selected |
| --- | --- |
| Mutate artifacts directly in the domain evaluator | Violates domain purity and makes atomic filesystem behavior impossible to test without I/O |
| Extend `ArtifactSource` with write methods | Changes the established read-only validation contract and gives unrelated validators mutation capability |
| Serialize the complete normalized artifact back to disk | Risks changing body formatting, comments, ordering, and content outside the permitted metadata fields |
| Write directly to the target file | Can leave truncated or partially written artifacts when a write fails |
| Use an append-only promotion history | Conflicts with the approved latest-metadata-only contract and adds persistence scope |
| Trust a caller-provided timestamp | Makes production audit timestamps caller-controlled and bypasses the required nondeterminism seam |
| Add a time or atomic-write dependency | The current scope can use injected time and standard-library filesystem primitives without a new dependency |
| Add a new adapter crate or architectural layer | The existing application and artifact-filesystem boundaries already provide the required seams |

## Consequences

### Positive

- Promotion decisions remain pure, deterministic, and independently testable.
- Existing read-only validation ports and callers remain unchanged.
- Atomic replacement and expected-source comparison prevent partial or stale
  writes from silently changing artifacts.
- Body content and unrelated files remain unchanged.
- Timestamp behavior is deterministic in tests without adding a dependency.
- Future CLI composition can reuse the application contract without moving
  lifecycle rules into command handling.

### Negative Or Tradeoffs

- The application gains two new ports and their in-memory test doubles.
- The filesystem adapter needs format-aware metadata patching for Markdown and
  Gherkin rather than reusing a general serializer.
- Same-directory rename semantics and expected-source conflict handling require
  filesystem integration tests on supported platforms.
- The flat promotion fields become part of the artifact metadata contract and
  must remain compatible with future validation and serialization work.

## Follow-Up Actions

- Add the pure promotion policy and lifecycle value types under the domain
  promotion capability.
- Add `ArtifactPromotionStore`, `Clock`, typed promotion errors, and the
  application promotion handler.
- Add a format-preserving filesystem promotion adapter and deterministic system
  clock implementation at the adapter/composition boundary.
- Add domain, application, filesystem, and acceptance tests before production
  implementation.
- Revisit CLI binding, exit-code taxonomy, and serialized promotion output under
  EPIC-004.
