# Architecture Decision Record

## Context

EPIC-001's `ArtifactSource` discovers only active canonical artifacts and
deliberately excludes `specs/archive/`. US-002 must compare recognized IDs across
active and historical artifacts, including archived packets, while preserving
EPIC-001's active-only behavior for existing callers.

The identity check is still a repository-boundary operation, so its discovery
must remain behind an application-owned port. The result should reuse the
existing candidate, diagnostic, and validation-report contracts.

## Decision

Keep the existing active `ArtifactSource` contract unchanged and add a separate
`ArtifactIdentitySource` port in the application layer for repository-wide
identity discovery. The filesystem source implements both roles, using distinct
discovery behavior for active validation and identity validation. The application
identity use case consumes the new port and passes normalized snapshots to pure
domain identity rules.

The new port returns the existing candidate type and existing typed discovery
error. A source-level failure remains terminal; a per-file read or recognition
failure remains a diagnostic candidate. No new crate, parser dependency, or
serialization boundary is introduced.

## Alternatives Considered

| Alternative | Reason not selected |
| --- | --- |
| Add an active/history scope parameter to `ArtifactSource` | Modifies the established EPIC-001 contract and makes active callers responsible for a broader policy choice |
| Return active and historical files from `ArtifactSource` and filter in the application | Violates the active source contract and moves discovery responsibility into orchestration |
| Create a second filesystem adapter with duplicated discovery logic | Duplicates the technology boundary and increases drift between equivalent file parsing paths |
| Let the identity domain read repository paths directly | Violates domain purity and the application-owned process-boundary rule |

## Consequences

### Positive

- EPIC-001 active validation remains behaviorally unchanged.
- Identity validation has an explicit, narrow seam for active plus historical
  discovery and an in-memory test double.
- Domain identity rules remain pure and independently testable.
- Existing candidate, diagnostic, ordering, and validation-report contracts are
  reused.

### Negative Or Tradeoffs

- The filesystem source implements two related application ports.
- Discovery policy must be tested separately for active and identity scopes.
- A new application entry point is required before the future CLI can expose both
  validation modes.

## Follow-Up Actions

- Add `ArtifactIdentitySource` and its in-memory test double in the application
  crate.
- Extend the filesystem adapter with repository-wide identity discovery while
  retaining active-only discovery.
- Add integration coverage for archived artifacts and scope exclusions.
- Link the identity use case and its tests to `REQ-002` and `DES-002`.
